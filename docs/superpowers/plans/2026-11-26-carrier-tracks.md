# Carrier Tracks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Institute carrier's track belts run round their wheels, locked to how far each track has run.

**Architecture:** Offline, `tools/split_moving_parts.py` cuts the two belts out of the carrier's hull, exports one scanned link per side (`TrackLinkL`, `TrackLinkR`) and writes each track's loop and link count to a generated Rust file. At runtime the carrier spawns that many copies of each side's link and places every copy from its two pins on the loop, shifted by `Carrier::tracks[side]`.

**Tech Stack:** Rust, Bevy 0.20, headless Blender 4.5 (`blender` on PATH) with numpy, gltfpack/glTF Transform via `tools/slim_dense_model.py`, Python `unittest`.

**Spec:** `docs/superpowers/specs/2026-11-26-carrier-tracks-design.md`

## Global Constraints

- Project rules in `CLAUDE.md`: imported models only; finish every runtime GLB with `python3 tools/compress_glb_textures.py <glb>` last; never hand-edit a generated GLB or generated `.rs`; precalculate once (no per-frame or per-load derivation of what the assets fix); no `unwrap()` in game logic; `use` order std, external, crate, super; `cargo clippy -- -D warnings`, `cargo fmt -- --check` and `cargo test` clean; update `doc/world-reference.md` (Institute carrier bullet) in the same change.
- Keep model fidelity: the link is the scan's own geometry and texture; no flattening of the belt, no lower-resolution link than the rest of the slimmed model.
- Wheel, sprocket, idler and roller node translations in the new GLB must equal the current ones (|Δ| ≤ 1e-4 model units): `carrier.rs` constants (`TRACK_ENDS`, `HALF_TRACK`, wheel radii by hub height, lamp mounts, collision) depend on the model frame.
- Links move with `Carrier::tracks[side]` (meters, the value the wheels roll with); moving forward, the lower run travels toward −Z in the model frame.
- The pipeline's source commands are in `tools/split_moving_parts.py`'s docstring (weld → split → `slim_dense_model.py` → `compress_glb_textures.py`); sources in `~/Projects/agentic/RoadSide-Picnic/models/vehicles/uhd/institute-carrier.glb`; scratch files under the session scratchpad, never in `assets/`.
- Playtests set `XDG_DATA_HOME` to a scratch folder.

## Review Focus

1. Removing the belt changes the scan's bounds, so `normalize` would re-center and re-ground the whole model: every hard-coded carrier constant would silently drift. Task 1 pins node translations.
2. The loop's closing point: a gap or a doubled link where arc length wraps. Task 2 tests closure.
3. Reversing and pivoting: negative and opposite `tracks` values on the two sides. Task 2 tests both.
4. Long play: `tracks` grows without bound (100 km = 1e5 m); f32 wrapping must not make links jitter or bunch. Task 2 tests a large run.
5. The hidden template links: they must neither render nor cast a shadow, and the copies must not inherit the hide. Task 3 checks in the playtest.

### Task 2: Links on a loop

**Files:**
- Create: `src/player/vehicle/track_loop.rs` (declare `mod track_loop;` in `src/player/vehicle.rs`)

**Interfaces:**
- Produces:
  - `pub(super) struct TrackLoop` with `pub(super) fn new(points: &[[f32; 2]]) -> TrackLoop` (closed polyline of (z, y)), `pub(super) fn length(&self) -> f32`, `pub(super) fn point(&self, s: f32) -> Vec2` (arc length `s` taken modulo the length, `rem_euclid`).
  - `pub(super) fn link_pose(track: &TrackLoop, x: f32, links: usize, index: usize, run: f32) -> Transform` — link `index` of `links` at arc length `index · length / links + run` (model units; `run` reduced modulo the length before adding). Its pins are `point(s − h)` and `point(s + h)`, `h = length / links / 2`; translation `(x, mid.y, mid.x)` where `mid` is the pins' midpoint; rotation about X turning the link's local −Z onto the direction from the rear pin to the front pin, so on the lower run (travel −Z) the rotation is identity and the tread faces −Y.

- [ ] **Step 1: Write the failing tests** (`#[cfg(test)] mod tests` in `track_loop.rs`, on a stadium like Task 1's):
  - `the_loop_closes`: the set of positions for `run = 0` equals the set for `run = length / links` (each link takes its neighbour's place, within 1e-5).
  - `links_are_evenly_spaced`: consecutive link centres (including last → first) differ in pin-to-pin distance by < 1 % round arcs and straights.
  - `a_lower_link_runs_rearward_going_forward`: a link on the lower run moves to smaller z as `run` grows by a little; on the upper run it moves to larger z.
  - `a_link_faces_out`: on the lower run the rotation is identity (within 1e-4); on the upper run the link's local −Y points +Y.
  - `reversing_runs_it_back`: `run = -d` puts each link where `run = length − d` does.
  - `a_long_drive_keeps_the_spacing`: with `run = 1e5 / 7.0` (100 km at the carrier's scale) spacing still within 1 %.
