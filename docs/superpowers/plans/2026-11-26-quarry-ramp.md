# Quarry Ramp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A dirt haul road that spirals from the Quarry rim diorama's drive down to its pit floor, walkable and drivable, cut into the scan with a shader cutaway.

**Architecture:** An offline tool bakes the ramp's centerline (quarry model units) into a generated Rust file. `roads.rs` grades it as a `Surface::Ramp` track at one constant grade; `terrain.rs` lets ramp legs override the diorama's ground; a world-aligned height image of the corridor drives a material extension that discards the quarry scan's fragments above the terrain there; scan pillars on the bed are dropped once.

**Tech Stack:** Rust, Bevy 0.20 (`ExtendedMaterial`, WESL), Python 3 + numpy for the tool.

**Spec:** `docs/superpowers/specs/2026-11-26-quarry-ramp-design.md`

## Global Constraints

- Work on branch `quarry-ramp`; commit messages `quarry-ramp: <imperative summary>` ending with the `Claude-Session:` line.
- Constant grade ≤ 0.20 on the whole ramp; bed half-width 4.5 m, shoulder 9.0 m.
- Fill ≤ 8 m and cut ≤ 3 m against the scan's ground; ramp runs ≥ 18 m (2 shoulders) apart in plan once ≥ 40 m apart along it.
- Cut image: 0.5 m texels, world-aligned; discard fragments > 0.05 m above it; "uncut" value `1.0e6`.
- Precalculate once: the path is baked by the tool; levels, the cut image and the filtered pillars are computed once (say why in a comment where it is at runtime).
- No `unwrap()` in game logic; systems named `verb_noun`; `cargo clippy -- -D warnings`, `cargo fmt -- --check` and `cargo test` pass.
- Do not edit the scan GLBs or `uhd_quarry_pit_ground.rs`; regenerate `quarry_ramp.rs` only through the tool.

## Review Focus

- **The streamed full scan arriving after the cut image exists, and streaming out and back in:** each new instance must draw with the cut material — test in Task 5 (`the_quarry_scan_draws_through_the_ramp_cut`).
- **The drive leg (Dirt, 11 m shoulder) overlapping the ramp's first leg inside the footprint:** the entrance must not get a step where the nearest-leg choice flips — covered by Task 3's grade test sampling from the drive's junction onward.
- **Click-to-move from the rim to the floor:** the A* router must find the ramp (pillars gone, grades passable) — test in Task 4 (`a_click_order_routes_down_the_ramp`).
- **Shadows and the depth prepass:** stone above the ramp must not shadow or occlude it — prepass shader in Task 5, checked in the Task 6 playtest screenshots.
- **The ramp's last leg meeting the floor:** no lip where the constant grade ends above the relief — Task 3's `the_ramp_ends_on_the_floor`.

### Task 1: Bake the ramp path

**Files:**
- Create: `tools/plan_quarry_ramp.py`, `tools/test_plan_quarry_ramp.py`
- Create (generated): `src/world/pillars/quarry_ramp.rs`

**Interfaces:**
- Produces: `src/world/pillars/quarry_ramp.rs`, an `include!`-able `&[Vec2]` literal of model-space points (x, z in model units), first point on the front edge's middle (`z = 0.41655`), headed by `// Generated by tools/plan_quarry_ramp.py from uhd_quarry_pit_ground.rs; do not edit.`
- Tool CLI: `python3 tools/plan_quarry_ramp.py src/world/pillars/uhd_quarry_pit_ground.rs src/world/pillars/quarry_ramp.rs [--grade 0.2] [--scale 110]`; prints length, max fill, max cut and closest runs.

- [ ] **Step 1: Write the failing tests** (`python3 -m unittest tools/test_plan_quarry_ramp.py -v`): `test_parses_the_relief_grid` (64×64 heights, `min`/`cell` match the file); `test_path_descends_to_the_floor` (on the real grid: length 180–320 m, end relief within 4 m of the grid's minimum); `test_path_stays_near_the_relief` (max fill ≤ 8 m, max cut ≤ 3 m at constant grade, relief smoothed as the search does); `test_runs_keep_apart` (points ≥ 40 m apart along the path are ≥ 18 m apart in plan); `test_writes_rust_points` (output parses as `Vec2::new(x, z)` lines and starts with the header).
- [ ] **Step 2: Run them; expect import failure.**
- [ ] **Step 3: Implement the tool.** Bilinear relief like `Relief::height` in `sites.rs` (grid = `(at - min) / cell - 0.5`, clamped). Search, as prototyped: Dijkstra over states (cell on a 32×32 grid spanning the footprint ±(0.45, 0.38), heading of 8, distance bucket of 2 m); start at the front middle heading −z with level 0 = relief at `(0, 0.41655)`; each step turns −45°/0/+45°; level = −grade × distance; relief = 3×3 mean at radius 0.02 units; step cost = `d · (dev²/25 + (cut ? dev²/9 : 0)) + 20 · |turn|` with `dev = level − relief`; goal = relief < floor + 4 m and |dev| < 1.5 m. Smooth the cell path with two Chaikin passes, resample at ~3 m, convert to model units, write the file.
- [ ] **Step 4: Run the tests; expect PASS.** Run the tool; expect about 226 m, fill ≈ 7 m, cut ≈ 2 m, closest ≈ 24 m.
- [ ] **Step 5: Commit** the tool, its test and the generated file.

### Task 5: Cut the scan over the ramp

**Files:**
- Create: `src/world/ramp_cut.rs`, `assets/shaders/ramp_cut.wesl`

**Interfaces:**
- Produces: `pub(super) type RampCutMaterial = ExtendedMaterial<StandardMaterial, RampCut>`; `RampCut { #[uniform(100)] bounds: Vec4 /* min x, min z, 1/width, 1/depth */, #[texture(101, sample_type = "float", filterable = false)] heights: Handle<Image> }` (R32Float, read with `textureLoad` at the nearest texel); `#[derive(Resource)] pub(super) struct RampCutImage(pub Handle<Image>, pub Vec4)`.
